# v2.7 之后的开发重点

检查日期：2026-09-29。下列为代码与资源审查得出的建议，未在本次发布中扩展实施。

## 当前基础

六个房间已迁移到代码像素绘制；藏书阁采用独立纵深布局。审稿、出版、签约作者、部门、书店、梦境、纪元和阅读器已经有实现。接下来应先让一轮出版流程完整可见，再扩展更多机制。

## 1. 优先修整经营入口

- 主编室 `DeskRoom.tsx` 的流水线筛选、标签和图标仍缺少 `cover_designing`，设计中的稿件会暂时消失在面板里。补全这个状态，标注剩余时间，并从审稿实际走到付印验收。
- 办公室三个入口都嵌入整个 `OfficeView`。拆成部门、版税消费、设置三个对应面板，避免点击茶水柜却看到所有管理内容。
- 核对启用部门对应的工位。目前画面按部门数量点亮前 N 个，未按部门类型逐个映射。

验收：新游戏完成征稿、审稿、签约、设计和出版；有设计部和无设计部两条路径都能解释稿件当前状态。保存后刷新，书、作者和部门均保留。

## 2. 完成房间与移动端交互验收

- 六个房间检查鼠标、键盘、触控入口；隐藏房间的面板和快捷键不互相影响。
- 检查 390px 手机竖屏、横屏和不同设备缩放：场景保持像素方格，按钮不重叠，面板可滚动。
- 统一所有房间的物件提示，增加需要操作时的像素标记。
- 检查旧页面/PWA 更新后加载新版本，覆盖存档导入导出、离线推进。

## 3. 按房间功能精修美术

- 办公室加入能看出部门职责的物件；作者室用不同种族和作者形象替换通用画像。
- 档案室的奖杯与日志卷数反映实际荣誉和年份。
- 书房完善落地壁炉与阅读角的空间关系。统一家具比例、光源和像素簇，减少大面积抖色。
- 添加少量可关闭的环境音和物件反馈之前，先确认整体视觉方向。

## 4. 书封（已改为代码绘制）

`src/art/covers.ts` 按书名 + 题材生成 40×56 封面：关键词选主图案、再加一个不搭的小道具、书名画成伪字形。24 张手绘封面已无损转成 `src/art/handCovers.ts` 的数据，优先于生成结果；`PixelCover` 不再加载 PNG（`public/covers/*.png` 与 manifest 仅留作原稿）。`node scripts/render-covers.mjs 12` 导出样张。

待办：给常见书名补关键词联想、扩充图案库，并让封面进入玩法（设计部等级决定图案档次、`cover_select` 给出多个方案、藏书阁展台显示真实封面）。
